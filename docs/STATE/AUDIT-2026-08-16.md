## FIXED

### HOOK-02 — the CUI guard failed open on git-magic filenames (**critical**, Law 1) · ADR-0409
`.githooks/pre-commit` read staged bytes via `git show ":$path"`, so a name beginning `!`,
`^`, `<digit>:` or `:(` parsed as git magic and returned **empty output** — read by every
content detector as "clean". A real schedule committed silently under `!plan.json`; a plain
`git add -A` stages such names. Fixed by resolving the index OID. Triple-verified: 6 tests
red by name → module 98 green · an independent bash battery (10 hostile shapes blocked, 4
benign controls still allowed, ADR-0152 exception intact) · mutation battery **4/4 by name**.

## LEAD-VERIFIED — awaiting fix

### MC-01 — a fired register OPPORTUNITY zeroes the activity's duration (**critical**, Law 2)
`engine/sra.py:1701` (and the twin in `engine/jcl.py`): a fired risk REPLACES the sampled
duration — `overrides[u] = max(0, impact)`. `ScheduleRisk.impact_days` is documented at
`sra.py:708` as *"**additive** working days when it fires (>=0 risk, **<0 opportunity**)"*, and
opportunities are a first-class product feature with their own 5x5 Opportunity matrix. For a
negative impact, `max(0, impact)` is **0** — the activity is replaced with a zero-duration
task instead of being shortened.

**Executable proof** (20-day driver → 5-day successor, focus = uid 2, one certain −5 d
opportunity on the driver):

| run | P50 |
| --- | --- |
| no register | 25.0 wd |
| −5 d opportunity | **5.0 wd** |
| correct if honoured | 20.0 wd |

The finish collapsed by the **full 20 days** of the driver, not by the opportunity's 5 — a
**15-working-day optimistic error** in a figure an SRA quotes. Law 2 calls a fast wrong number
worthless; an optimistic one in a testimony deliverable is worse than worthless.

**Why this is NOT a blind fix.** ADR-0359 made a fired risk *replace* the duration, and that
was measured against SSI's own export — but only for **positive** impacts. Replacement is
meaningless for a negative one, and the field's own docstring says **additive**. The natural
correction is: positive → replacement (ADR-0359, parity-locked); negative → subtract from the
sampled duration, floored at 0. That is defensible from the documented semantics, but the
**parity** question — what SSI itself reports for a fired opportunity — needs the reference
export as its oracle, exactly like MF-05. Implement with red-first tests and, if an SSI
opportunity export exists, pin against it; if it does not, ship the documented-additive
semantic and say plainly in the ADR that the parity leg is UNVERIFIED.

**Also check the JCL twin**: `engine/jcl.py` replicates the same replacement block, so an
opportunity almost certainly zeroes there too — the fix and its tests must cover both engines
(ADR-0408 made them mirror each other deliberately).

### MF-02 — the EVM workbook exports a fabricated `0.0` for every NOT_APPLICABLE index (**high**, Law 2)
`web/app.py:2983` writes each index as
`indices[k].value if k in indices and indices[k].value is not None else ""`.
That guard **never fires**: `_na_index()` (`engine/metrics/evm.py:259`) builds the NA result
with `value=0.0`, not `None` — and its own docstring reads *"NA, never a fabricated 0."*

**Executable proof** (schedule with no `budgeted_cost` at all):

| index | status | value | workbook cell |
| --- | --- | --- | --- |
| SPI | NOT_APPLICABLE | 0.0 | **0.0** |
| CPI | NOT_APPLICABLE | 0.0 | **0.0** |
| TCPI | NOT_APPLICABLE | 0.0 | **0.0** |

An analyst opening the hand-out sees CPI = 0.00 — which reads as catastrophic cost
performance — where the truth is "this file carries no cost data". That inverts the design
system's standing rule (*missing shows an em dash, never a fabricated figure*) and Law 2,
in an exported artefact that leaves the tool and can be quoted.

**Planned fix:** gate the cell on `status is NOT_APPLICABLE` (the field that actually
carries the meaning), not on `value is not None`; render the page's em dash / blank
consistently. Check every other consumer of `MetricResult.value` for the same false guard —
this is a *class*, not a single site, and the class is what the fix's tests must pin.
**Not yet implemented** — needs red-first tests, a sandbox blast-radius pass, and a
mutation battery like MF-01's.

## FIXED (2)

### MF-01 — TCPI was scored with its PASS direction INVERTED (**high**, Law 2) · ADR-0410
`engine/metrics/evm.py:332` — `_index()` hardcodes `Direction.GE` for all three indices.
SPI/CPI are correctly "higher is better"; **TCPI is inverted by definition**: TCPI > 1 means
the remaining work needs *better* efficiency than achieved so far.

Three independent confirmations:
1. **The repo's own published definition contradicts the code** — `web/help.py:571`:
   *"TCPI **<= 1.0** means the remaining work can complete within budget … > 1.0 requires
   better-than-planned performance"*, and the formula line says `(pass <= 1.0 …)`.
2. **Executable probe**: a project needing 1.6× efficiency → `verdict=PASS`; a comfortable
   project at 0.25× → `verdict=FAIL`. Exactly backwards.
3. **Two existing tests PIN THE DEFECT** (ADR-0385 stale-guard class, 3rd instance) and must
   be repointed in the same commit:
   - `tests/test_projects/test_pass_fail_battery.py:801` — asserts a **blown** (over-budget)
     project's TCPI is `PASS` at 1.17;
   - `tests/engine/metrics/test_evm.py:364` — asserts TCPI `0.5` (comfortable) is `FAIL`.

**Impact:** the affordability dimension shows green precisely on the projects that cannot
afford their remaining work — the worst possible failure in a testimony context.
**FIXED (ADR-0410, v1.0.208):** `_index()` takes an explicit direction; TCPI is `LE` at
1.0. THREE oracles pinned the defect and were repointed. Sandbox-measured before the
tree was touched (4 failures / 430, all bug-pinning); mutation battery 4/4 by name.
The NASA `.aft` confirms the FORMULA was always right — only the verdict was wrong, so
no parity value moves and `help.py` needed no edit.
