## The contract to replicate (verified this session, PR-9a round)

- `_shell_tools(*, export_title="", big=True)` — app.py:7702: `⤓ EXCEL` **only** when
  `export_title` non-empty; `⛶ ENLARGE` unless `big=False`; **never emits ▦** (no helper
  does — ▦ exists only in per-page JS today: trend.js:203, mission.js:89).
- `_panel_head(title, *, tools="", prov="")` — app.py:7725: `<div class=panel-head><h2>…`.
- The panel (not the button) usually carries `data-export="…"` to an EXISTING endpoint
  (`_analysis_export_attr` app.py:7741 is the model). panelkit.js follows button-attr first,
  panel-attr second; no attr = dead click.
- panelkit.js (95 lines): delegated listener; every control must sit inside `.panel`;
  ⛶ toggles `.is-big` (overlay vs tile is base.css's call; single-open + Escape for
  overlays); ▦ toggles the panel's `.sf-drawer[hidden]` — **silently no-ops without a
  drawer, and NO page emits one today**, so every new ▦ must ship its drawer in the same
  change; ⤓ navigates to the export URL.
- Canonical converted panel (`_forecast_explainer`, app.py:8804-8811):
  `<div class=panel>{_panel_head(..., tools=_shell_tools(...), prov=...)}` →
  `<p class=sf-take>` → `<p class=muted>` read-me → content. The ⤓ law is strict: only when
  the export's columns COVER what the panel draws ("never a dead or lying link" — the
  forecast panel deliberately drops ⤓ because the ruler plots more than the export carries).
- panelkit.js is a PER-BODY include (~20 sites), NOT layout-global; chartframe.js's ⤢/zoom
  toolbar on `.chart-host` is a DIFFERENT contract — don't confuse the two.
