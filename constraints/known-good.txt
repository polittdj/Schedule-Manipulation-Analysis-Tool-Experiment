# constraints/known-good.txt — one FULL resolution that was measured green (ADR-0346)
#
# The complete transitive closure of `pip install -e '.[dev]'` on CPython 3.11, captured
# from a clean venv on 2026-08-03 at v1.0.160 and verified by the full gate on that tree.
# Use it to reproduce a known-good build exactly — an offline/mirrored operator install,
# a "it worked yesterday" bisect, or an incident where the question is whether the code
# or the resolution changed:
#
#     pip install -e '.[dev]' -c constraints/known-good.txt
#
# WHAT IT IS NOT. CI's `test` matrix deliberately does NOT use this file. That matrix is
# the canary: it resolves fresh every run so an upstream release that breaks us shows up
# as a red build here rather than as a surprise on the operator's machine. Pinning the
# canary would trade a known-late failure for an unknown-late one. The bounds in
# `pyproject.toml` are what keep the canary inside a tested band; this file is what makes
# a single point inside that band exactly repeatable.
#
# THE httpx2 TRANSITION, recorded because it is the live example of the risk these bounds
# exist for. starlette 1.3.1 (below) imports `httpx2` for its TestClient, falls back to
# `httpx` with a `StarletteDeprecationWarning`, and raises `RuntimeError` if NEITHER is
# installed. `pyproject.toml`'s `filterwarnings` silences that warning — silencing is not
# bounding, which is the audit finding this ADR answers. A starlette that finishes the
# transition and DROPS the httpx fallback would break every web test at import time, so
# starlette is pinned here and fastapi (which is what actually pulls it) is bounded below
# a 1.0 in `pyproject.toml`. starlette itself is not a declared dependency — nothing under
# `src/` imports it (verified: zero matches) — so bounding it belongs in this file, not in
# `project.dependencies`.
#
# MAINTENANCE. `tests/test_dependency_bounds.py` fails if any pin here falls outside the
# range `pyproject.toml` declares for that distribution, so a bound change and this file
# can never drift apart silently. Regenerate with:
#
#     python3.11 -m venv /tmp/kg && /tmp/kg/bin/pip install -e '.[dev]' \
#       && /tmp/kg/bin/pip freeze --exclude-editable --all \
#          | grep -viE '^(pip|wheel)==' | sort -f
#
# `--all` is load-bearing and was learned the hard way: a plain `pip freeze` silently omits
# setuptools (pip treats it, `pip` and `wheel` as "self" packages), so the first capture dropped
# the ONE pin that exists for a CVE remediation. `test_known_good_covers_every_runtime_and_dev_
# requirement` caught it on its first run. `pip` and `wheel` are filtered back out: constraining
# the resolver that is already running is meaningless.
#
# `requests` / `urllib3` below are pip-audit's own dependencies and are DEV-ONLY. They are
# forbidden RUNTIME distributions (Law 1, src/schedule_forensics/net_guard.py) and the
# egress guard checks `project.dependencies`, not this file — see that module's docstring.
