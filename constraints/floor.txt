# constraints/floor.txt — the DECLARED MINIMUM, pinned so CI can execute it (ADR-0346)
#
# Every version here is exactly the lower bound `pyproject.toml` declares for that
# distribution. The `floor` job in .github/workflows/ci.yml installs with
#
#     pip install -e . -c constraints/floor.txt pytest pytest-cov httpx
#
# and runs the whole suite plus the parity gate against it. That turns "we support
# pytest 8.0" (and `[tool.pytest.ini_options] minversion = "8.0"`) from an assertion
# into a measurement.
#
# WHY THIS FILE EXISTS. Before ADR-0346 nothing bounded the resolution and nothing
# tested the bottom of it, so the same tree passed or failed on whatever pip resolved
# that day — proven, not theorised: pytest 8.0.2 FAIL / 8.4.2 FAIL / 9.1.1 PASS on one
# commit (ADR-0345). THREE of the declared floors were also simply untrue when measured:
#
#   * `pydantic>=2` did not install at all beside `fastapi>=0.110` — fastapi 0.110.0
#     excludes pydantic 2.0.0/2.0.1/2.1.0, so the pair was unsatisfiable at its own
#     declared floors.
#   * once installable, pydantic 2.0.2-2.5.3 FAILED `tests/model/test_schedule.py::
#     test_cache_does_not_perturb_hash_or_equality`: pydantic's generated `hash_func`
#     hashed `self.__dict__.values()`, which on a frozen `Schedule` includes the
#     `tasks_by_id` cache — `TypeError: unhashable type: 'mappingproxy'`. 2.6.0 is the
#     first release that passes, so 2.6 is the floor now declared.
#   * `fastapi>=0.110` declared support for an AIR-GAP VIOLATION — see the note beside
#     the fastapi pin below. That one is Law 1, and it is why this file exists.
#
# SCOPE. Only the distributions the floor job installs appear here, because only those
# are proved by running it. The QC tools (ruff / mypy / bandit / pip-audit / setuptools)
# are deliberately ABSENT: their *output* is version-sensitive by design — `ruff format`
# rewrote this repo's markdown when it crossed 0.16, and `mypy --strict` gains checks
# between releases — so pinning them low and running the gate would measure the tool,
# not the product. They are bounded narrowly in `pyproject.toml` instead, and
# `tests/test_dependency_bounds.py` calls that out as an ADVISORY floor rather than an
# executed one.
#
# MAINTENANCE. `tests/test_dependency_bounds.py` fails if any line here stops matching
# the lower bound declared in `pyproject.toml`, in either direction. Raise the bound in
# `pyproject.toml` and this file in the same commit.

# --- runtime (project.dependencies) -------------------------------------------------
pydantic==2.6.0
# 0.110.2, not 0.110 — a LAW 1 floor. 0.110.0/0.110.1 serve pydantic's
# `https://errors.pydantic.dev/<ver>/v/missing` inside 422 validation-error bodies, which
# `tests/web/test_airgap.py` correctly reports as an external reference on 10 routes. The
# first run of this very job is what found it.
fastapi==0.110.2
uvicorn==0.29.0
jinja2==3.1.6
python-multipart==0.0.18

# --- test execution (project.optional-dependencies.dev) -----------------------------
# httpx is what starlette's TestClient rides on; see constraints/known-good.txt for the
# httpx2 transition this pair is exposed to.
pytest==8.0.0
pytest-cov==5.0.0
httpx==0.27.0
